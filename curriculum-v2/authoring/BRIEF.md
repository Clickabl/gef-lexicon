# Authoring brief: one language for the gef app's "Meet this language" lesson and its script lesson

(Hand this file to an authoring agent with the language tag and the language specifics. `<drop>` is any scratch directory; merge the result with `python3 curriculum-v2/authoring/ingest_drop.py <drop> <lang>...`, then run `npm run validate`.)

You are authoring candidate curriculum data for ONE language. Everything you write is typed, language-neutral FACTS filling fixed SLOTS; the app computes differences against whatever languages a learner already knows and teaches the writing in a lesson of its own. Accuracy beats volume: use only what you are certain of, verify with WebSearch/WebFetch (Wiktionary, Wikipedia, CLDR, official orthography pages), and mark every doubt in NEEDS.md. Never invent. Everything is `candidate`, never claimed verified.

## What the lesson is (so you can judge what to write)

- **Meet {language}** has five short stops: where it comes from; how it looks (writing); how it sounds; what is different (grammar traits); words you already know. It must never feel like a wall of text: short facts, things to hear and tap.
- **The script lesson** ("Learn the Arabic alphabet") is a lesson of its own for one writing layer. For each group of 2 to 6 symbols the learner sees a big tile per symbol, taps it to hear a word that contains it, sees its name, its sound, its positional shapes if it joins, and a very common example word with the symbol highlighted; then they do a hear-and-pick and a match; at the end a review. So the data for EVERY symbol must be rich and correct.

## Rules for the letter data (the script lesson depends on them)

- `writing.layers`: the layer ids, primary first. A layer is one writing system the learner meets (see INTRO_FACTS.md). Give each layer `kind`, `script` (ISO 15924), `role` (exactly one `primary`), `direction`, `has_case`, `joined`, `vowels`, `symbols`, `marked`, `punctuation`.
- `symbols`: the layer's inventory as units a learner learns, in conventional order. Digraphs that are really one unit in the language's own alphabet (Spanish `ñ`; Swahili `ch`) count as symbols; digraphs spelled from letters a reader already has are explained in sounds, not listed. Accented/variant letters that are separate letters in the alphabet are symbols; accents on otherwise ordinary letters are `mark` facts. A character layer (`logographic`) has an empty `symbols` list and is carried by at least 12 example characters.
- `writing.<layer>.example.<key>` for EVERY symbol, plain Latin a to z included (and for every punctuation mark and every `marked` letter that is a distinct shape). Value: a very common, concrete, short word (at most 7 letters) that contains the symbol, preferably starting with it, easy to picture, not a proper noun, not a loanword if a native word is as common. Qualifiers: `highlight` (the symbol exactly as it appears in the word), `ipa` (the word, broad phonemic), `sound` (the symbol's own sound in this language, broad IPA, e.g. `b`; for a symbol with more than one sound give the main one), `reading` (REQUIRED when the script is not Latin: a Latin transliteration of the symbol, e.g. `b`, `ka`, `g/k`, or of the character/word for characters), `name` (the letter's own name in its script with a Latin transliteration, when it has one), `looks_like` (only where a Latin letter resembles it and sounds different), `forms` (for joining scripts: the shapes in order isolated, initial, medial, final; a letter that does not join forward has two), `parts` (a character's components).
- `writing.<layer>.group.<n>` (n from 1): groups of 3 to 5 symbols in a good TEACHING order for a beginner who does not know the script: by shape families (Arabic), by articulation row (Devanagari, kana, Hangul), or by easy-first familiarity (Cyrillic letters that look and sound like Latin first, then false friends, then new letters). Every symbol of the layer appears in exactly one group; a character layer groups its example characters (4 to 6 per group, easy and common first).
- `marks`: `writing.<layer>.mark.<id>` for the marks that change a sound or vowel (use the mark ids and roles in slots.json), each with an `example` word and its `example_ipa`.
- Sounds: IPA of the standard variety; at least three tricky sounds for an English speaker; at least two contrast pairs; `tones.system` (and at least four `tones.example.*` if tonal); `stress.pattern`; `spelling.predictability`.
- Grammar: ALL traits in slots.json get a value; examples for every trait whose value is not `none`. Pick the closest value and say in NEEDS.md when the fit is imperfect.
- Overview: genealogy (family, branches, related languages from the registry, origin regions, script ids as ISO 15924 codes), `reach.regions`, a greeting as `hook.target` and two common non-greeting decoys.
